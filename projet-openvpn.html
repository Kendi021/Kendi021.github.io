Déploiement d'un serveur VPN OpenVPN — Accès distant sécurisé

Mise en place pas à pas d'un serveur OpenVPN sur Ubuntu Server 22.04 pour offrir un accès distant chiffré à un réseau d'entreprise. Création d'une infrastructure de clés (PKI) avec Easy-RSA, configuration du pare-feu et du NAT, chiffrement AES-256-GCM, génération d'un profil client .ovpn et sécurisation du serveur. Projet réalisé en environnement de formation (machine virtuelle).

Contexte

L'entreprise fictive ENT-BTS souhaite permettre à ses administrateurs de se connecter au réseau interne depuis l'extérieur, de façon chiffrée et authentifiée. On déploie un serveur OpenVPN qui crée un « tunnel » entre le poste distant et le serveur : tout le trafic du client passe alors de manière sécurisée par ce tunnel.

Paramètres à personnaliser

Toutes ces valeurs se règlent en haut des fichiers. Adapte-les à ton labo si besoin.

Élément Valeur d'exemple
Système serveur Ubuntu Server 22.04 LTS
Nom d'hôte vpn-server
Interface publique eth0
IP publique du serveur 203.0.113.10
Protocole / Port UDP / 1194

Environnement de formation uniquement. L'IP 203.0.113.10 et le nom d'interface eth0 sont des exemples : remplace-les par les tiens (commande ip a pour voir ton interface). Exécute les commandes avec sudo.

Prérequis

  • Une VM ou un serveur Ubuntu Server 22.04 avec accès root / sudo.
  • Une IP publique (ou une redirection du port 1194/udp sur la box, en labo).
  • Un accès SSH au serveur et un client OpenVPN sur le poste distant (OpenVPN Connect, Tunnelblick…).

1 Préparation du serveur

On met le système à jour, on nomme le serveur, puis on active le routage IP (indispensable pour faire transiter le trafic des clients).

# Mise à jour du système
sudo apt update && sudo apt upgrade -y

# Nom d'hôte
sudo hostnamectl set-hostname vpn-server

# Activer le transfert de paquets (routage IPv4)
echo 'net.ipv4.ip_forward=1' | sudo tee /etc/sysctl.d/99-openvpn.conf
sudo sysctl --system

Vérification

sysctl net.ipv4.ip_forward   # Doit renvoyer : net.ipv4.ip_forward = 1

2 Pare-feu UFW & NAT

On autorise le SSH (pour ne pas se couper l'accès) et le port OpenVPN, puis on configure le NAT (MASQUERADE) : les clients VPN (réseau 10.8.0.0/24) sortiront vers Internet en empruntant l'IP publique du serveur.

# Ouvrir SSH puis le port OpenVPN
sudo ufw allow OpenSSH
sudo ufw allow 1194/udp

2.1 — Règle de NAT

Ajoute ce bloc tout en haut du fichier /etc/ufw/before.rules (avant la ligne *filter) :

*nat
:POSTROUTING ACCEPT [0:0]
-A POSTROUTING -s 10.8.0.0/24 -o eth0 -j MASQUERADE
COMMIT

Puis autorise le transfert par défaut dans /etc/default/ufw :

DEFAULT_FORWARD_POLICY="ACCEPT"
# Recharger le pare-feu
sudo ufw disable && sudo ufw enable
sudo ufw status verbose

3 Installation & PKI (Easy-RSA)

On installe OpenVPN puis on crée l'autorité de certification (CA) et les certificats. Le VPN repose sur une PKI : la CA signe le certificat du serveur et ceux des clients, ce qui garantit que seuls les postes autorisés peuvent se connecter.

sudo apt install -y openvpn easy-rsa

# Créer un dossier de travail pour la PKI
make-cadir ~/easy-rsa
cd ~/easy-rsa

# Initialiser la PKI et créer l'autorité de certification
./easyrsa init-pki
./easyrsa build-ca nopass            # nom commun : ex. ENT-BTS-CA

# Certificat + clé du serveur
./easyrsa build-server-full server nopass

# Paramètres Diffie-Hellman + clé tls-auth (HMAC anti-DoS)
./easyrsa gen-dh
openvpn --genkey --secret ta.key

3.1 — Copier les fichiers vers OpenVPN

sudo cp pki/ca.crt pki/issued/server.crt pki/private/server.key \
        pki/dh.pem ta.key /etc/openvpn/server/
La clé privée de la CA (pki/private/ca.key) ne doit jamais quitter un endroit sûr : c'est elle qui permet de signer de nouveaux certificats.

4 Configuration du serveur

On crée le fichier /etc/openvpn/server/server.conf. Il définit le port, le réseau virtuel distribué aux clients, le chiffrement et les options poussées (route par défaut + DNS).

# /etc/openvpn/server/server.conf
port 1194
proto udp
dev tun

ca   ca.crt
cert server.crt
key  server.key
dh   dh.pem
tls-auth ta.key 0

# Réseau virtuel attribué aux clients
server 10.8.0.0 255.255.255.0

# Chiffrement moderne
cipher AES-256-GCM
auth  SHA256

# Tout le trafic du client passe par le VPN + DNS
push "redirect-gateway def1 bypass-dhcp"
push "dhcp-option DNS 1.1.1.1"
push "dhcp-option DNS 8.8.8.8"

keepalive 10 120
persist-key
persist-tun
user  nobody
group nogroup
status /var/log/openvpn/status.log
verb 3
# Démarrer et activer le service au boot
sudo systemctl enable --now openvpn-server@server
sudo systemctl status openvpn-server@server

Vérification

ip a show tun0   # L'interface tun0 (10.8.0.1) doit exister

5 Génération d'un client (.ovpn)

On crée le certificat du client, puis on assemble un fichier .ovpn « tout-en-un » (configuration + certificats inclus) à importer sur le poste distant.

cd ~/easy-rsa
./easyrsa build-client-full client-admin nopass

Modèle de fichier client-admin.ovpn (les balises seront remplies avec le contenu des certificats) :

client
dev tun
proto udp
remote 203.0.113.10 1194     # IP publique du serveur
resolv-retry infinite
nobind
persist-key
persist-tun
remote-cert-tls server
cipher AES-256-GCM
auth SHA256
key-direction 1
verb 3

# Coller ici le contenu des fichiers :
<ca>       ... pki/ca.crt ...                 </ca>
<cert>     ... pki/issued/client-admin.crt ... </cert>
<key>      ... pki/private/client-admin.key ... </key>
<tls-auth> ... ta.key ...                       </tls-auth>
Astuce : un petit script bash peut assembler automatiquement ce .ovpn en concaténant le modèle et les certificats — pratique pour générer rapidement plusieurs clients.

6 Connexion & vérification

On importe le .ovpn dans le client OpenVPN du poste distant, on se connecte, puis on vérifie que le tunnel fonctionne.

# Sur le SERVEUR : voir les clients connectés
sudo cat /var/log/openvpn/status.log

# Sur le CLIENT, une fois connecté :
ping 10.8.0.1        # La passerelle VPN doit répondre
curl ifconfig.me     # Doit afficher l'IP PUBLIQUE DU SERVEUR (203.0.113.10)

Si curl ifconfig.me renvoie l'IP du serveur, c'est gagné : tout le trafic du client sort bien par le tunnel chiffré. ✔

7 Sécurisation du serveur

On durcit l'accès au serveur pour éviter les intrusions.

# Protection anti-bruteforce sur SSH
sudo apt install -y fail2ban
sudo systemctl enable --now fail2ban

Puis dans /etc/ssh/sshd_config, on renforce le SSH :

PermitRootLogin no
PasswordAuthentication no     # Connexion SSH par clé uniquement
sudo systemctl restart ssh
  • Fail2ban bannit temporairement les IP qui multiplient les échecs de connexion.
  • SSH par clé + root désactivé : la surface d'attaque est fortement réduite.
  • Le pare-feu UFW n'ouvre que l'essentiel (SSH + 1194/udp).

Récapitulatif

À la fin du projet, l'infrastructure dispose de :

  • Un serveur vpn-server sous Ubuntu avec OpenVPN actif sur UDP 1194.
  • Une PKI Easy-RSA (CA, certificat serveur, certificats clients).
  • Un tunnel chiffré en AES-256-GCM distribuant le réseau 10.8.0.0/24.
  • Un NAT permettant aux clients de sortir par l'IP publique du serveur.
  • Un profil client-admin.ovpn prêt à importer.
  • Un serveur durci (UFW, Fail2ban, SSH par clé).
