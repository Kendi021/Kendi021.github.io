Déploiement Active Directory — ENT-BTS

Mise en place pas à pas d'un domaine ent-bts.local sur un serveur Windows Server 2016/2019, avec création automatisée de l'annuaire (utilisateurs, groupes, unités d'organisation), stratégies de groupe, sécurité et sauvegarde. Projet réalisé en environnement de formation (machine virtuelle).

Contexte de l'entreprise

L'entreprise fictive ENT-BTS souhaite centraliser la gestion de ses comptes et de ses postes. On installe un contrôleur de domaine unique qui jouera aussi les rôles DNS et DHCP.

Paramètres à personnaliser

Toutes ces valeurs se modifient en haut des scripts. Adapte-les à ton labo si besoin.

Élément Valeur d'exemple
Nom du serveur SRV-AD01
Domaine Active Directory ent-bts.local
Nom NetBIOS ENT-BTS
IP fixe du serveur 192.168.10.10 / 24
Passerelle 192.168.10.1
Étendue DHCP 192.168.10.100 → 192.168.10.200
Groupes RH, IT, Marketing, Ventes, Direction
Utilisateurs ~30 comptes (import CSV)
Environnement de formation uniquement. Le domaine .local et ces réglages sont volontairement simples : ne pas utiliser en production réelle. Exécute chaque script PowerShell en administrateur.

Prérequis

  • Une VM Windows Server 2016 ou 2019 (Hyper-V, VirtualBox ou VMware).
  • Un compte Administrateur local et un mot de passe défini.
  • Une carte réseau en mode « réseau interne » ou « hôte uniquement » pour le labo.
  • Console PowerShell ouverte en tant qu'administrateur.

1 Création du domaine

On fixe l'adresse IP du serveur, on le renomme, puis on installe le rôle Active Directory et on le promeut en contrôleur de domaine. C'est la « fondation » du projet.

1.1 — Adresse IP fixe et DNS

Un contrôleur de domaine doit avoir une IP fixe et pointer son DNS vers lui-même.

# Paramètres réseau — à adapter
$IP        = "192.168.10.10"
$Prefixe   = 24
$Passerelle = "192.168.10.1"
$Interface = (Get-NetAdapter | Where-Object Status -eq "Up").Name

# Appliquer l'IP fixe
New-NetIPAddress -InterfaceAlias $Interface -IPAddress $IP `
    -PrefixLength $Prefixe -DefaultGateway $Passerelle

# DNS = le serveur lui-même (obligatoire pour un DC)
Set-DnsClientServerAddress -InterfaceAlias $Interface -ServerAddresses $IP

1.2 — Renommer le serveur

Rename-Computer -NewName "SRV-AD01" -Force
Restart-Computer   # Redémarrage nécessaire

1.3 — Installer le rôle AD DS

Install-WindowsFeature AD-Domain-Services -IncludeManagementTools

1.4 — Créer la forêt et promouvoir le contrôleur

Cette commande crée le domaine ent-bts.local et installe automatiquement le DNS.

Import-Module ADDSDeployment

Install-ADDSForest `
    -DomainName "ent-bts.local" `
    -DomainNetbiosName "ENT-BTS" `
    -ForestMode "WinThreshold" `
    -DomainMode "WinThreshold" `
    -InstallDns:$true `
    -Force:$true
# Le serveur redémarre tout seul à la fin.

Vérification

Get-ADDomain         # Doit afficher ent-bts.local
Get-ADDomainController # Doit afficher SRV-AD01

2 Services réseau (DNS & DHCP)

Le DNS a déjà été installé avec l'AD. On ajoute maintenant le serveur DHCP qui distribuera automatiquement les adresses IP aux postes clients.

2.1 — Vérifier le DNS

Get-DnsServerZone   # La zone ent-bts.local doit être présente

2.2 — Installer et configurer le DHCP

# Paramètres DHCP — à adapter
$Debut   = "192.168.10.100"
$Fin     = "192.168.10.200"
$Masque  = "255.255.255.0"
$Routeur = "192.168.10.1"
$DNS     = "192.168.10.10"

# Installer le rôle
Install-WindowsFeature DHCP -IncludeManagementTools

# Créer l'étendue (la plage d'adresses)
Add-DhcpServerv4Scope -Name "LAN-ENT-BTS" `
    -StartRange $Debut -EndRange $Fin -SubnetMask $Masque

# Options : passerelle + serveur DNS
Set-DhcpServerv4OptionValue -Router $Routeur -DnsServer $DNS `
    -DnsDomain "ent-bts.local"

# Autoriser le serveur DHCP dans l'AD
Add-DhcpServerInDC -DnsName "SRV-AD01.ent-bts.local" -IPAddress $DNS

Vérification

Get-DhcpServerv4Scope   # Affiche l'étendue 192.168.10.100-200

3 Unités d'organisation, groupes & utilisateurs

On organise l'annuaire : une OU par service, un groupe par service, puis on importe les comptes depuis un fichier CSV.

3.1 — Créer les unités d'organisation (OU)

$Base = "DC=ent-bts,DC=local"

# OU parente de l'entreprise
New-ADOrganizationalUnit -Name "ENT-BTS" -Path $Base `
    -ProtectedFromAccidentalDeletion $true

# Une OU par service
$Services = "RH","IT","Marketing","Ventes","Direction"
foreach ($s in $Services) {
    New-ADOrganizationalUnit -Name $s -Path "OU=ENT-BTS,$Base" `
        -ProtectedFromAccidentalDeletion $true
}

3.2 — Créer les groupes

foreach ($s in $Services) {
    New-ADGroup -Name "GG_$s" -GroupScope Global -GroupCategory Security `
        -Path "OU=$s,OU=ENT-BTS,$Base" `
        -Description "Groupe du service $s"
}

3.3 — Préparer le fichier des utilisateurs

Crée un fichier utilisateurs.csv (séparateur point-virgule) à côté du script :

Prenom;Nom;Login;Service
Marie;Durand;mdurand;RH
Paul;Martin;pmartin;IT
Sophie;Bernard;sbernard;Marketing
Lucas;Petit;lpetit;Ventes
Emma;Robert;erobert;Direction
# ... ajoute autant de lignes que nécessaire (~30)

3.4 — Créer les comptes depuis le CSV

$Base = "DC=ent-bts,DC=local"
$MotDePasse = ConvertTo-SecureString "Azerty2026!" -AsPlainText -Force

Import-Csv ".\utilisateurs.csv" -Delimiter ";" | ForEach-Object {
    $ou = "OU=$($_.Service),OU=ENT-BTS,$Base"

    New-ADUser `
        -Name "$($_.Prenom) $($_.Nom)" `
        -GivenName $_.Prenom `
        -Surname $_.Nom `
        -SamAccountName $_.Login `
        -UserPrincipalName "$($_.Login)@ent-bts.local" `
        -Path $ou `
        -AccountPassword $MotDePasse `
        -ChangePasswordAtLogon $true `
        -Enabled $true

    # Ajouter l'utilisateur au groupe de son service
    Add-ADGroupMember -Identity "GG_$($_.Service)" -Members $_.Login
}
Le paramètre -ChangePasswordAtLogon $true oblige l'utilisateur à changer son mot de passe à la première connexion : une bonne pratique simple.

Vérification

Get-ADUser -Filter * -SearchBase "OU=ENT-BTS,DC=ent-bts,DC=local" | Measure-Object
Get-ADGroupMember -Identity "GG_IT"

4 Stratégies de groupe (GPO)

Une GPO applique des règles automatiquement aux utilisateurs/postes d'une OU. Exemple simple : verrouiller la session après 10 minutes d'inactivité.

$Base = "DC=ent-bts,DC=local"

# Créer la GPO
$gpo = New-GPO -Name "Verrouillage session" `
    -Comment "Verrouille l'écran après 10 min"

# Régler le délai d'inactivité (600 s = 10 min)
Set-GPRegistryValue -Name "Verrouillage session" `
    -Key "HKCU\Software\Policies\Microsoft\Windows\Control Panel\Desktop" `
    -ValueName "ScreenSaveTimeOut" -Type String -Value "600"

# Lier la GPO à l'OU de l'entreprise
New-GPLink -Name "Verrouillage session" -Target "OU=ENT-BTS,$Base"

Vérification

Get-GPO -All | Select-Object DisplayName
gpresult /r   # Sur un poste client, pour voir les GPO appliquées

5 Sécurité (politique de mot de passe)

On renforce la politique de mots de passe du domaine : longueur minimale, complexité et expiration.

Set-ADDefaultDomainPasswordPolicy -Identity "ent-bts.local" `
    -MinPasswordLength 8 `
    -ComplexityEnabled $true `
    -MaxPasswordAge "90.00:00:00" `
    -PasswordHistoryCount 5 `
    -LockoutThreshold 5 `
    -LockoutDuration "00:15:00"
  • 8 caractères minimum et complexité activée (majuscule, chiffre, etc.).
  • Mot de passe à renouveler tous les 90 jours.
  • Verrouillage du compte après 5 essais ratés, pendant 15 minutes.

Vérification

Get-ADDefaultDomainPasswordPolicy

6 Sauvegarde de l'Active Directory

On installe l'outil de sauvegarde Windows, puis on sauvegarde l'état système qui contient toute la base de l'annuaire (fichier NTDS.dit).

# Installer la fonctionnalité de sauvegarde
Install-WindowsFeature Windows-Server-Backup

# Sauvegarder l'état système vers le disque E: (à adapter)
wbadmin start systemstatebackup -backupTarget:E: -quiet
L'état système inclut l'AD, le registre et la configuration du serveur : c'est la sauvegarde clé pour restaurer un contrôleur de domaine.

Vérification

wbadmin get versions   # Liste les sauvegardes disponibles

Récapitulatif

À la fin du projet, l'infrastructure ENT-BTS dispose de :

  • Un contrôleur de domaine SRV-AD01 sur ent-bts.local (AD DS + DNS).
  • Un serveur DHCP distribuant la plage 192.168.10.100-200.
  • 5 OU, 5 groupes et ~30 utilisateurs organisés par service.
  • Une GPO de verrouillage de session liée à l'entreprise.
  • Une politique de mot de passe renforcée et une sauvegarde de l'AD.
